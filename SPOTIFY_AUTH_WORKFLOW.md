# Spotify Local Auth Workflow

This repository includes a local-only CLI helper at `scripts/spotify-token-utils.mjs` for Spotify auth setup. Use it when you need to:

- generate a Spotify authorization URL
- exchange the returned authorization code for tokens
- encrypt the refresh token for use in `SPOTIFY_TOKEN_ENCRYPTED`

---

## Required environment variables

The local helper reads `.env` automatically from the repository root. The following env vars are used:

- `SPOTIFY_CLIENT_ID`
- `SPOTIFY_CLIENT_SECRET` (optional; if absent, PKCE flow is used)
- `SPOTIFY_REDIRECT_URI`
- `SPOTIFY_TOKEN_KEY`
- `SPOTIFY_TOKEN_ENCRYPTED`
- `SPOTIFY_REFRESH_TOKEN` (optional for encryption if not passed via CLI)

Do not rename these vars. The script and the runtime backend expect them exactly.

---

## Step 1: Generate the authorization URL

Run:

```bash
npm run spotify:auth-url
```

If you want to override env values on the command line:

```bash
npm run spotify:auth-url -- --client-id YOUR_CLIENT_ID --redirect-uri http://localhost:3000/callback
```

If `SPOTIFY_CLIENT_SECRET` is not set, the script will default to PKCE mode and print a `code_verifier`.

## Expected redirect callback format

After successful login, Spotify will redirect the browser to your configured `SPOTIFY_REDIRECT_URI` using a URL in this form:

```text
https://your-redirect-uri?code=AUTH_CODE&state=STATE_VALUE
```

If something failed, Spotify may instead return an error like:

```text
https://your-redirect-uri?error=access_denied&error_description=...
```

The values you should copy are:

- `code` — the authorization code used in the next exchange step
- `state` — should match the value generated by the script if you want to verify the request

### What to copy

- open the URL printed by the command in your browser
- after login/approval, Spotify will redirect to `SPOTIFY_REDIRECT_URI`
- copy the `code` value from the redirect URL
- also copy the `state` if you want to verify it matches
- if PKCE was used, save the `code_verifier` shown by the script

---

## Step 2: Exchange the authorization code for tokens

Use one of the following based on your auth mode.

### Normal client-secret flow

If `SPOTIFY_CLIENT_SECRET` is set, run:

```bash
npm run spotify:exchange-token -- --code YOUR_CODE
```

### PKCE flow

If you use PKCE, run:

```bash
npm run spotify:exchange-token -- --code YOUR_CODE --code-verifier YOUR_CODE_VERIFIER
```

### What to copy

- copy `refresh_token` from the response JSON
- you may also keep `access_token` for manual API testing, but the backend only needs `refresh_token`

---

## Step 3: Encrypt the refresh token

After you have the Spotify refresh token, encrypt it locally with:

```bash
npm run spotify:encrypt-token -- --token YOUR_REFRESH_TOKEN --key YOUR_TOKEN_KEY
```

If you prefer environment variables instead of flags:

```bash
export SPOTIFY_REFRESH_TOKEN=your_refresh_token
export SPOTIFY_TOKEN_KEY=your_token_key
npm run spotify:encrypt-token
```

### What to copy

- copy the resulting encrypted value and store it in `SPOTIFY_TOKEN_ENCRYPTED`
- keep `SPOTIFY_TOKEN_KEY` secret and consistent with the key used for encryption

---

## Optional: Verify decryption

To verify the encrypted token decrypts correctly:

```bash
npm run spotify:decrypt-token -- --encrypted YOUR_ENCRYPTED_VALUE --key YOUR_TOKEN_KEY
```

If the output is your original refresh token, the encrypted value and key are correct.

---

## Command summary

- `npm run spotify:auth-url` — generate the login URL
- `npm run spotify:exchange-token -- --code YOUR_CODE` — exchange code for tokens (normal auth)
- `npm run spotify:exchange-token -- --code YOUR_CODE --code-verifier YOUR_CODE_VERIFIER` — exchange code for tokens (PKCE)
- `npm run spotify:encrypt-token -- --token YOUR_REFRESH_TOKEN --key YOUR_TOKEN_KEY` — encrypt refresh token
- `npm run spotify:decrypt-token -- --encrypted YOUR_ENCRYPTED_VALUE --key YOUR_TOKEN_KEY` — verify the encrypted token

---

## Notes

- `spotify:auth-url` reads `.env` automatically.
- Do not store `SPOTIFY_CLIENT_SECRET` or `SPOTIFY_TOKEN_KEY` in source control.
- Keep `SPOTIFY_TOKEN_ENCRYPTED` and `SPOTIFY_TOKEN_KEY` in your deployment env only.
